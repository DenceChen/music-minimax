# Music MiniMax - 产品需求文档

> 当前版本：v1.0.0
> 最后更新：2026-05-09

## 1. 愿景

让每个人都能轻松创作属于自己的歌曲。

---

## 2. 核心功能

### 2.1 必需功能（P0）

| 功能 | 描述 |
|------|------|
| **对话输入** | 用户通过自然对话描述歌曲需求 |
| **AI 歌词生成** | 基于用户描述自动生成歌词（含缓存机制） |
| **歌词编辑** | 用户可自由编辑生成的歌词 |
| **AI 歌曲生成** | 基于歌词异步生成完整歌曲 |
| **在线播放** | 支持在页面内播放生成的歌曲 |
| **歌曲下载** | 支持下载生成的 mp3 文件 |
| **用户认证** | 注册/登录系统，保存创作历史 |

### 2.2 应有功能（P1）

| 功能 | 描述 |
|------|------|
| **风格选择** | 支持流行/摇滚/民谣/嘻哈等风格 |
| **时长选择** | 支持 15s / 30s / 60s 等时长 |
| **历史记录** | 查看和管理所有创作歌曲 |
| **任务进度** | 实时显示歌曲生成进度 |

### 2.3 可有功能（P2）

| 功能 | 描述 |
|------|------|
| **社交分享** | 生成分享链接，支持微信/微博分享 |
| **歌词翻译** | 多语言歌词支持 |

---

## 3. 用户故事与验收标准

### US-01：普通用户创作第一首歌

**身份**：普通用户（无音乐背景）  
**场景**：看到广告后尝试创作第一首歌  
**需求**：用自然语言描述脑海中的歌曲想法

**验收标准**：
- [ ] 用户输入"我想写一首关于夏天的歌"
- [ ] 系统回复理解用户意图（自然语言处理）
- [ ] 系统生成完整歌词（流行风格）
- [ ] 用户可编辑歌词后确认
- [ ] 系统异步生成歌曲并显示进度
- [ ] 用户可播放最终歌曲
- [ ] 用户可下载歌曲到本地

---

### US-02：音乐爱好者编辑歌词

**身份**：音乐爱好者（有一定音乐素养）  
**场景**：对 AI 生成的歌词不满意，想要调整  
**需求**：自由编辑歌词后生成歌曲

**验收标准**：
- [ ] 用户看到系统生成的歌词
- [ ] 用户可直接修改歌词文本（文本编辑器）
- [ ] 用户可调整段落顺序
- [ ] 修改后的歌词用于歌曲生成
- [ ] 最终歌曲反映用户编辑的内容

---

### US-03：专业用户指定风格

**身份**：独立音乐人  
**场景**：为不同项目创作不同风格的音乐  
**需求**：指定歌曲风格（流行/摇滚/民谣/嘻哈等）

**验收标准**：
- [ ] 用户在输入需求时可指定风格
- [ ] 也可在歌词生成后选择风格
- [ ] 不同风格生成差异明显的歌曲
- [ ] 风格选择影响歌词和编曲

---

### US-04：查看历史创作

**身份**：活跃用户  
**场景**：之前创作过几首满意的歌，想要回顾  
**需求**：查看历史创作记录

**验收标准**：
- [ ] 用户可以进入"我的作品"页面
- [ ] 看到所有历史歌曲列表（含创建时间、状态）
- [ ] 点击可回放之前创作的歌曲
- [ ] 可查看当时的歌词内容
- [ ] 可重新下载历史歌曲

---

### US-05：删除不满意作品

**身份**：普通用户  
**场景**：创作了一首不满意的歌，想要删除  
**需求**：删除歌曲及本地文件

**验收标准**：
- [ ] 用户可在歌曲详情页删除歌曲
- [ ] 删除后本地 mp3 文件同步删除
- [ ] 数据库记录标记为已删除
- [ ] 删除前有确认提示

---

### US-06：重新生成歌曲

**身份**：普通用户  
**场景**：对生成的歌曲不满意，想要重新尝试  
**需求**：复用已有歌词重新生成

**验收标准**：
- [ ] 用户可点击"重新生成"按钮
- [ ] 复用上一次歌词（不消耗歌词生成配额）
- [ ] 重新排队生成新歌曲
- [ ] 新歌曲替换原歌曲

---

### US-07：用户注册与登录

**身份**：新用户 / 已注册用户  
**场景**：首次使用 / 再次访问  
**需求**：注册账号并登录系统

**验收标准**：
- [ ] 新用户可使用邮箱注册
- [ ] 密码需符合安全要求（至少 6 位）
- [ ] 注册后自动登录
- [ ] 已注册用户可登录
- [ ] 登录后可访问所有功能

---

### US-08：每日生成限制

**身份**：所有登录用户  
**场景**：防止资源滥用  
**需求**：每用户每日最多生成 5 首歌曲

**验收标准**：
- [ ] 每日凌晨（00:00）重置配额
- [ ] 达到 5 次后禁止创建新任务
- [ ] 前端显示剩余生成次数
- [ ] 达到限制时提示"今日生成次数已用完"

---

## 4. 非功能需求

### 4.1 性能指标

| 指标 | 目标值 |
|------|--------|
| 对话响应时间 | < 3 秒 |
| 歌词生成时间 | < 10 秒 |
| 歌曲生成时间 | < 60 秒 |
| 页面加载时间 | < 2 秒 |

### 4.2 可用性

- 支持 Chrome / Safari / Firefox 最新两个版本
- 移动端适配（响应式布局）
- 网络断开时友好提示

### 4.3 安全要求

- 所有 MiniMax API Key 存储在 `.env.local`，不暴露在前端
- 密码使用 bcrypt 哈希存储
- 用户每日生成次数在服务端校验
- 用户只能访问自己的歌曲

---

## 5. 技术约束

- **前端**：Next.js 14 App Router + TypeScript + Tailwind + shadcn/ui
- **后端**：Next.js API Routes（同项目内）
- **数据库**：SQLite + Prisma
- **认证**：NextAuth Credentials Provider
- **播放器**：wavesurfer.js
- **存储**：本地 mp3 存储到 `/public/songs/`
- **日志**：pino（结构化 JSON 日志）
- **测试**：Playwright
- **部署**：docker-compose up（localhost:3000）

| createdAt | DateTime | 创建时间 |
| expiresAt | DateTime | 过期时间 |

### TokenUsage
| 字段 | 类型 | 描述 |
|------|------|------|

| userId | String | 外键 |

## 7. API 端点

| 端点 | 方法 | 描述 |
|------|------|------|
| `/api/auth/[...nextauth]` | GET/POST | 登录/登出 |
| `/api/chat` | POST | 对话理解 |
| `/api/lyrics` | POST | 生成歌词（含缓存） |
| `/api/music/generate` | POST | 创建歌曲生成任务 |
| `/api/music/status/[taskId]` | GET | 轮询任务状态 |
| `/api/songs` | GET | 获取用户所有歌曲 |
| `/api/songs/[taskId]` | DELETE | 删除歌曲及文件 |
| `/api/songs/[taskId]/regenerate` | POST | 重新生成 |
| `/api/admin/usage` | GET | 消耗统计（管理端） |

## 8. 错误处理

| 错误场景 | 处理方式 |
|----------|----------|
| MiniMax API 超时 | 指数退避重试（1s → 2s → 4s → 8s），最多 3 次 |
| 限流（429） | 等待 30s 后重试 |
| 任务失败 | 状态改为 failed，显示友好错误 |
| 重复点击 | 防抖 1s 内禁止重复提交 |
| 网络断开 | 检测 navigator.onLine，断网时禁用操作 |
| Token 超限 | 返回 429，提示"今日生成次数已用完" |
| 未登录 | 重定向到登录页 |
